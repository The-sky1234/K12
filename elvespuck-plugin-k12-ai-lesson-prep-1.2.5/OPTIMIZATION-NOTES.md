# 1.2.5 模型调用稳定性优化

本版针对“模型调用失败/模型不存在/占位Key误判”做了加固：

- `models-secrets.json` 中的示例占位 Key 不再被当成有效 Key。
- 默认选择改为“系统默认模型（推荐）”，避免宿主没有 `deepseek/deepseek-chat` 时直接失败。
- 模型调用链：显式直连（有有效Key）→ 指定模型宿主网关 → 宿主系统默认模型 → 已配置备用直连 → 本地兜底。
- 直连请求对 429、408、5xx、超时、网络抖动自动指数退避重试 2 次。
- 宿主 `engine.generate` 的字符串/text/content/outputText/message.content 等返回形式均兼容，并拦截空响应。
- AI 页面增加“测试模型”按钮，可直接查看每条通道的连通结果。
- 超时时间从 60 秒提升到 90 秒，降低大模型首 token 较慢导致的误失败。

## 推荐部署方式

1. 如果 AgentOS/Core 已经配置了可用默认模型：直接选择“系统默认模型（推荐）”，无需在插件里放 Key。
2. 如果必须直连 DeepSeek：在服务端插件数据目录的 `models-secrets.json` 写入真实 Key；不要把真实 Key 打进要分发的 ZIP。
3. 安装后先点“测试模型”，看到至少一条 `✓` 再做 AI 生成。

注意：任何插件都无法在“宿主无可用模型且没有有效 API Key、或网络完全不可用”的情况下保证真实模型一定成功；本版会最大化自动恢复，并在最终失败时保留本地模板兜底，避免业务页面直接不可用。
